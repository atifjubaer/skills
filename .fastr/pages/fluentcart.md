FluentCart's licensing module stores every activation in `fct_license_sites.site_url`. Nothing in the schema requires a URL, so desktop apps, MV3 extensions, VSTs and CLI tools activate through the same public endpoints as a WordPress plugin by sending a stable `device://<uuid-v4>` in that field.

Rules that matter:
- Generate the UUID once per install, persist it in the OS credential store, never derive it from hardware serials/MAC, never rotate it on update (rotation burns a paid seat).
- Every response carries `server_time_unix` and a pre-computed `expires_in_days`. Decide entitlement from `expires_in_days`, never from parsing `expires` against the local clock.
- Clock guard: persist `server_time_unix` together with `checked_at_local`; if `now - checked_at_local < -300s` the clock moved backwards → treat as tampered. Do not also police forward jumps (legitimate clock fixes).
- `site_url` must be URL-encoded — the `:` and `/` in `device://` break form parsing raw.

Implemented as `fc_generate_device_licensing_boilerplate` in `server/src/cards/fluentcart/tools.ts` for tauri_rust, chrome_extension, python and cpp_vst.
